## Architecture

- Before writing code, read ARCHITECTURE.md and the accepted ADRs that touch the area you change. Follow them.
- If the project has neither, derive the architecture from the existing code and suggest rs-architecture to the user.
- If a change would contradict ARCHITECTURE.md or an accepted ADR, stop and ask the user. The way forward is a new ADR that supersedes it, never silent deviation.
- When an architecture decision is made, record it with the rs-architecture-decision skill.
- Never weaken or skip an architecture test to make a change pass.
